# 1. PROJECT OVERVIEW

## 1.1 Introduction

AI Mystery Room is an AI-powered interactive mystery investigation platform where users become detectives and solve fictional criminal investigation cases generated dynamically by Artificial Intelligence.

Unlike traditional mystery games that provide predefined stories and fixed answers, AI Mystery Room generates unique investigation scenarios based on the story or situation submitted by the user.

The AI acts as the mystery creator and investigation designer.

Users provide a short scenario, story idea, or mysterious situation. Based on the input, the AI generates a complete fictional investigation containing:

* A mystery storyline.
* A set of suspects.
* One actual culprit.
* Motives and relationships.
* Investigation evidence.
* WhatsApp-style fictional conversations.
* AI-generated photographs.
* Fictional CCTV recordings.
* Witness statements.
* Hidden clues.
* Contradictions and misleading evidence.

The user must investigate the available evidence, connect the clues, identify inconsistencies, and ultimately select the person responsible for the mystery.

The platform evaluates the user's final decision based on the actual solution generated by the AI.

## 1.2 Core Concept

**Give AI a story. Let AI create a mystery. Become the detective and solve it.**

Example:

User Input:

"Four college friends went on a weekend trip. The next morning, one of them disappeared from the resort. Nobody knows what happened."

AI generates:

1. A complete mystery involving four suspects.
2. A timeline of events.
3. Fictional WhatsApp conversations between the friends.
4. Resort CCTV evidence.
5. Photographs taken during the trip.
6. Witness statements.
7. Hidden contradictions.
8. A final culprit with a logically consistent explanation.

The user investigates all the evidence and identifies the culprit.

## 1.3 Product Vision

To create an immersive AI-powered detective experience where every investigation is unique, interactive, challenging, and logically solvable.

2. Generate a mystery storyline.
3. Generate suspects.
4. Select one culprit.
5. Generate motives and alibis.
6. Generate investigation timelines.

## 4.4 AI Media Generation

The system should support three types of synthetic evidence.

**Images:**

* Crime scene photographs.
* Suspect photographs.
* Object photographs.
* Location photographs.
* Screenshots of fictional documents.

**Video:**

* CCTV-style recordings.
* Short surveillance sequences.
* Scene reconstruction clips.

**Text:**

* WhatsApp-style conversations.
* Emails.
* Witness statements.
* Police reports.
* Personal notes.

Implementation requirement:

Use a media-provider abstraction.

Gemini should handle text-based mystery generation. Image and video generation must use compatible media-generation providers configured through the backend.

If video generation is unavailable, the system should support generated CCTV-style image sequences with timestamps and a simulated playback interface.

All evidence must be clearly identified as fictional and AI-generated.

# 7. AI MYSTERY GENERATION ENGINE

This is the most important backend component.

The AI must generate a complete investigation rather than just a story.

## 7.1 Mystery Generation Logic

The AI must follow this sequence internally:

STEP 1: Analyze the scenario.

STEP 2: Identify the central mystery.

STEP 3: Create the actual sequence of events.

STEP 4: Decide the actual culprit before generating evidence.

STEP 5: Create suspects.

STEP 6: Define each suspect's:

* Identity.
* Relationship with the victim.
* Motive.
* Opportunity.
* Alibi.
* Hidden information.
* Potential involvement.

STEP 7: Generate the actual investigation timeline.

STEP 8: Generate evidence.

STEP 9: Introduce logical contradictions.

STEP 10: Introduce misleading clues.

STEP 11: Validate that the evidence supports the actual solution.

STEP 12: Generate the final solution and explanation.

CRITICAL:

The culprit and the underlying truth must be established before the evidence is generated.

The AI must not randomly choose a culprit after the investigation has already been created.

## 7.2 Mystery Data Structure

Gemini must return structured JSON.

Example:

{
"title": "The Midnight Disappearance",
"description": "A person disappeared from a resort.",
"category": "Disappearance",
"difficulty": "Medium",

"victim": {
"name": "Alex Morgan",
"description": "A 24-year-old student"
},

"suspects": [
{
"id": "S1",
"name": "Daniel",
"role": "Friend",
"motive": "Personal disagreement",
"publicAlibi": "Claims to have slept early"
}
],

"culpritId": "S2",

"timeline": [
{
"time": "20:30",
"event": "Everyone arrives at the resort"
}
],

"evidence": [
{
"id": "E1",
"type": "chat",
"title": "WhatsApp Conversation",
"description": "Conversation between two suspects",
"content": {},
"importance": "high",
"relatedSuspects": ["S1", "S2"]
}
],

"solution": {
"culpritId": "S2",
"motive": "The actual motive",
"explanation": "Complete explanation",
"evidenceConnections": ["E1", "E2"]
}
}

This is an illustrative structure. The production schema must include all fields defined in the backend models.

## 7.3 Logical Consistency Validation

The AI must verify:

* Exactly one culprit exists.
* Every suspect has a consistent identity.
* The timeline does not contain impossible events.
* Evidence timestamps are consistent.
* The culprit's motive is established.
* The final explanation is supported by evidence.
* At least two independent clues support the solution.
* Red herrings are misleading but explainable.
* The case can be solved without guessing.

If validation fails, the backend must request a correction from Gemini.

Allow a maximum of three generation or repair attempts before returning a controlled error.

Example:

CHAT: Daniel ↔ Michael

10:32 PM — Daniel:
"Are you still awake?"

10:34 PM — Michael:
"Yes. Why?"

10:35 PM — Daniel:
"Did you move the bag?"

10:36 PM — Michael:
"Not here. Don't talk about this on chat."

* Sender name.
* Receiver name.
* Timestamp.
* Message content.
* Conversation date.
* Related suspects.
* Hidden clues.

UI:

Display conversations inside a realistic messaging-inspired interface.

## 8.2 AI-Generated Images

Generate fictional investigation photographs.

Examples:

* Crime scene.
* Suspicious object.
* Broken window.
* Footprints.
* Torn documents.
* Damaged equipment.
* Suspicious vehicle.

Each image must have:

* Evidence ID.
* Image URL.
* Title.
* Description.
* Timestamp.
* Location.
* Related suspects.
* Investigation notes.

The image generation system should generate media based on the mystery's established facts.

## 8.3 CCTV Evidence

Generate fictional surveillance evidence.

Each recording must contain:

* Camera ID.
* Camera location.
* Recording date.
* Start timestamp.
* End timestamp.
* Video URL or generated frame sequence.
* Short description.
* Important timestamps.

Example:

CAMERA 04 — MAIN CORRIDOR

Recording: 11:30 PM – 11:45 PM

11:32 PM:
A person enters the corridor.

11:36 PM:
The corridor lights suddenly turn off.

11:40 PM:
A second person appears near the storage room.

The user must be able to play, pause, and inspect the recording.

If real video generation is not configured, implement CCTV frame sequences with playback controls and timestamp overlays.

## 8.4 Witness Statements

Generate statements from witnesses.

Each statement must contain:

* Witness name.
* Role.
* Statement.
* Time of interview.
* Reliability indicator.
* Related suspects.

Some statements may contain inconsistencies.

## 8.5 Documents and Reports

Generate fictional documents such as:

* Police reports.
* Entry registers.
* Emails.
* Receipts.
* Personal diaries.
* Medical reports where appropriate to the fictional scenario.
* Location access records.

All documents must have realistic formatting while remaining clearly fictional.

# 13. AI EVALUATION ENGINE

Evaluate the user's investigation.

Scoring system: 100 points.

Suggested scoring:

| Parameter                      | Points |
| ------------------------------ | -----: |
| Correct culprit identification |     50 |
| Explanation quality            |     25 |
| Supporting evidence selection  |     15 |
| Logical reasoning              |     10 |
| Total                          |    100 |

If the user identifies the wrong culprit, they should not receive the culprit-identification points.

The explanation quality can be evaluated by Gemini using the actual case solution and evidence.

The evaluation must distinguish between:

* Correct culprit with strong reasoning.
* Correct culprit with weak reasoning.
* Incorrect culprit with reasonable reasoning.
* Incorrect culprit with unsupported reasoning.

# 16. BACKEND API SPECIFICATION

Base URL:

/api/v1

## Authentication APIs

POST /auth/register

Register a new user.

POST /auth/login

Authenticate user.

GET /auth/me

Retrieve authenticated user details.

POST /auth/logout

Logout.

## Mystery APIs

POST /mysteries/generate

Generate a new mystery using AI.

Request:

{
"scenario": "Four friends went on a trip...",
"category": "Disappearance",
"difficulty": "Medium",
"setting": "Resort"
}

Response:

{
"success": true,
"message": "Mystery generated successfully",
"mysteryId": "generated-id",
"status": "ready"
}

GET /mysteries/:id

Retrieve mystery information without revealing the solution.

GET /mysteries

Retrieve the user's mysteries.

DELETE /mysteries/:id

Delete a mystery owned by the authenticated user.

## Evidence APIs

GET /mysteries/:id/evidence

Retrieve all evidence.

GET /mysteries/:id/evidence/:evidenceId

Retrieve a particular evidence item.

## Investigation APIs

POST /investigations/start

Start an investigation.

GET /investigations/:id

Retrieve investigation progress.

PUT /investigations/:id/notes

Save investigation notes.

PUT /investigations/:id/connections

Save evidence connections.

PUT /investigations/:id/bookmarks

Update bookmarked evidence.

## Verdict APIs

POST /investigations/:id/verdict

Submit final verdict.

Request:

{
"selectedSuspectId": "S2",
"reasoning": "My explanation...",
"supportingEvidence": ["E1", "E3"]
}

Response:

{
"success": true,
"result": {
"correct": true,
"score": 87,
"explanation": "..."
}
}

The complete culprit information should only be returned after successful verdict submission.

All endpoints must enforce authentication or guest-session authorization as applicable.

# 19. SECURITY REQUIREMENTS

1. Never expose the Gemini API key.
2. Hash user passwords.
3. Validate every API request.
4. Protect authenticated routes.
5. Verify investigation ownership.
6. Prevent users from accessing other users' private investigations.
7. Never expose the culprit before verdict submission.
8. Never trust frontend-submitted scores.
9. Store the actual solution on the backend.
10. Rate-limit AI generation endpoints.
11. Limit scenario input length.
12. Validate uploaded media.
13. Restrict file sizes.
14. Use environment variables for credentials.
15. Clearly label all generated evidence as fictional.

All AI-generated crime scenes, messages, documents, and recordings must remain within fictional game scenarios. The system must not generate evidence intended to impersonate real people or mislead real-world investigations.

* Invalid mystery ID.
* Missing evidence.
* Duplicate verdict submission.
* Unauthorized access.
